\begin{abstract}
When the same model scores 16.67 on GPQA from one leaderboard and
49.0 from another, the 32-point gap is uninterpretable without
knowing which evaluation harness, prompt template, temperature, and
n-shot count each source used---yet these fields are absent from
virtually every public record, despite being known to shift scores by
15+ percentage points \citep{alzahrani-2024-benchmarks}. Cross-source
scores are therefore \emph{silently incommensurable}.

We ingest \textbf{\totalrecords{}} evaluation records from
\textbf{\totalsources{}~sources} into the Every Eval Ever (EEE)
schema \citep{evaleval-2026}, covering \totalmodels{}~models and
\totalbenchmarks{}~benchmarks. Among \collisionn{}~independent
collision pairs (confounded by model identity and source quality),
metadata completeness predicts score divergence (Spearman
$\rho = \spearmanrho{}$, effective $n \approx \effectiven{}$). A
controlled experiment on \expmodels{}~instruction-tuned models
(\expruns{}~runs) supports the causal interpretation: temperature
and prompt format explain partial $R^2 = \prtwotempfive{}$ and
$\prtwofmtfive{}$ on 5-shot GSM8K---far below the overturn bound
$\overturnbound{}$. This association matters because independent
re-evaluation is structurally impossible (only \collisionpairs{}
collision pairs from \totalrecords{} records), pipeline artefact
rates are high (\pwcartifacts{} of Papers With Code records fail
semantic validation), and prompt template and temperature have
\textbf{\promptcoverage{}} valid coverage. We propose
\textbf{EvalSpec~v0.1}, a machine-readable specification that
converts unmeasured confounders into required fields, and release
our dataset, pipeline, and analysis code under CC-BY-4.0.
\end{abstract}

\section{Introduction}\label{sec:intro}
% ===================================================================

A benchmark score is not a direct measurement of model
capability---it is a measurement \emph{under a specific evaluation
configuration}. When that configuration is unrecorded, the score
is causally uninterpretable. \citet{alzahrani-2024-benchmarks}
show a 14.9-point MMLU gap on LLaMA~65B attributable entirely to
harness choice (HELM vs.\ lm-evaluation-harness);
\citet{biderman-2024-lessons} document comparable shifts from
prompt format, tokenisation, and generation configuration on MMLU
\citep{hendrycks-2021-mmlu}, GSM8K \citep{cobbe-2021-gsm8k}, and
HumanEval \citep{chen-2021-humaneval}. These are not sensitivity
curios: they are evidence of unmeasured confounding, variables
that affect the observed score $S$ independently of model
capability $M$ and whose omission from public records makes
cross-source comparisons non-identifiable.

The confounding set is well-defined: harness identity and
version, n-shot count, prompt template, temperature, and scoring
mode (log-likelihood ranking, generation-based with extraction,
preference, or execution). The GPQA case is illustrative:
Qwen2.5-72B-Instruct scores 16.67 on one leaderboard and 49.0
on another---a 32-point gap attributable post-hoc to scoring-mode
divergence, a confounder recorded by neither source. The gap is
not evidence of unreliable models; it is evidence of unidentified
evaluation conditions.

Worse, the problem cannot be resolved by independent re-evaluation.
Across 29,331~records from 11~sources we find only 16~collision
pairs versus 69~expected under random assignment---a deficit driven
by Open LLM Leaderboard~v2 (OLv2) evaluating a near-disjoint model
population (excluding OLv2: $z = 1.4$, n.s.). Pipeline artefact
rates are high (57\% of Papers With Code records fail semantic
validation), and \citet{singh-2025-illusion} document analogous
reliability failures at the platform level for preference
leaderboards. Documentation is therefore the only available
identification strategy: when re-evaluation is structurally
impossible and ingestion is semantically untrustworthy, recorded
configuration is the sole instrument for assessing cross-source
comparability.

\paragraph{Contributions.}
\textbf{(C1)}~A cross-source, schema-based audit of confounder
coverage: ingesting \totalrecords{}~records from
\totalsources{}~sources into the Every Eval Ever (EEE) schema
\citep{evaleval-2026} (\totalmodels{}~models,
\totalbenchmarks{}~benchmarks), we find prompt template and
temperature have 0\% valid coverage.
\textbf{(C2)}~Observational evidence that metadata completeness
predicts score divergence (Spearman $\rho = -0.871$, $n = 8$,
effective $n \approx 3$), supported by a controlled experiment on
\expmodels{} models (\expruns{} runs) showing partial $R^2$ values
for temperature and prompt format fall below the overturn bound.
\textbf{(C3)}~\textbf{EvalSpec v0.1}, a schema-validated
specification that converts unmeasured confounders into required
recorded fields, grounded in a causal audit of which fields block
the highest-impact backdoor paths from configuration to score.
We release dataset, pipeline, schema, and analysis code under
CC-BY-4.0. Four testable claims structure the analysis:
\textbf{H1}~(metadata gap), \textbf{H2}~(structural fragmentation),
\textbf{H3}~(documentation as reliability signal), and
\textbf{H4}~(pipeline fragility).

\section{Key Concepts}\label{sec:definitions}
% ===================================================================

An \emph{evaluation record} is a single JSON document conforming
to the EEE schema, capturing one model's result on one benchmark
from one source via four blocks: \texttt{model\_info},
\texttt{eval\_library} (harness), \texttt{source\_metadata}, and
\texttt{evaluation\_results}. Different harnesses can produce
different scores for the same model--benchmark because they
differ in tokenisation, prompt formatting, and answer extraction
\citep{biderman-2024-lessons}; we identify 11~distinct harnesses
(Table~\ref{tab:sources}). We describe as the \emph{structural
wall} the phenomenon that sources measuring the same constructs
may still be uncomparable because they evaluate non-overlapping
model subsets---a data-collection problem that no amount of
documentation can fix.

\subsection{Causal Framework}\label{sec:causal}

Following \citet{pearl-2009-causality}, we represent an observed
score $S$ as a function of model capability $M$ and evaluation
configuration $C = \{$harness identity, harness version, n-shot,
prompt template, temperature, scoring mode, quantization,
software version$\}$:
\begin{equation*}
  M \;\rightarrow\; S \;\leftarrow\; C
\end{equation*}
In most public records, $C$ is unobserved. This is unmeasured
confounding in the sense of \citet{cinelli2020sensitivity}:
variables that affect $S$ independently of $M$, whose omission
biases cross-source comparisons. The fields in
Table~\ref{tab:terminology} are the observable proxy for $C$;
\S\ref{sec:coverage} quantifies how much of $C$ remains
unobserved across 29,331~records.

Cross-source comparison is equivalent to estimating the ATE of
$M$ on $S$ while $C$ varies freely between sources, which is
non-identifiable without recording $C$. The
$\rho = -0.871$ association (\S\ref{sec:collisions}) is
consistent with this framing: partial measurement of $C$
(Tulu-3-8B pairs, harness~+~n-shot documented) coincides with
low divergence; full omission (Qwen2.5-72B, completeness = 0)
coincides with maximum divergence ($|\Delta| = 32.3$~pp). The
causal model is used here as a diagnostic and as a field-selection
rationale for EvalSpec (\S\ref{sec:evalspec}); the observational
base of 8~collision pairs is too small for credible effect
estimation, and interventional evidence is provided in
\S\ref{sec:experiment}.

\section{Related Work}\label{sec:related}
% ===================================================================

\paragraph{Benchmark sensitivity.}
\citet{alzahrani-2024-benchmarks} show score gaps of up to 15 points
on MMLU from harness choice alone, within a controlled
single-benchmark experiment. \citet{biderman-2024-lessons} identify
prompt format, tokenisation, and generation configuration as key
reproducibility axes and recommend reporting them---but do not
measure ecosystem compliance.
\citet{polo-2024-tinybenchmarks} show that a 100-item subset of
MMLU preserves ranking order under consistent conditions, a
property that breaks under methodology divergence. We quantify how
often the ecosystem records these axes
($<$0.1\% for prompt template and temperature) and show that the
public ecosystem is too fragmented for within-benchmark comparisons
to arise naturally at scale (16~collision pairs from
\totalrecords{}~records; driven by OLv2, $z=1.4$ n.s.\ without it).

\paragraph{Strategic leaderboard behaviour.}
\citet{singh-2025-illusion} audit Chatbot Arena across 2M battles
and document platform-level gaming: private multi-variant testing,
access asymmetries, and score instability for identical checkpoints
under different aliases. Our contribution is complementary: we show
that the cross-platform metadata infrastructure for detecting or
explaining such discrepancies is absent ecosystem-wide, making
independent verification structurally impossible at scale.

\paragraph{Evaluation infrastructure and documentation.}
The two dominant open harnesses---lm-evaluation-harness
\citep{gao-2021-framework} and HELM \citep{liang-2022-holistic}---
differ in defaults for n-shot, normalisation, and prompt template.
Integrated platforms (LightEval \citep{fourrier-2024-lighteval},
OpenCompass \citep{contributors-2023-opencompass}, EKA-EVAL
\citep{kim-2025-ekaeval}) track per-run metadata \emph{within}
their pipelines but provide no cross-platform comparison mechanism;
the EEE schema complements them by standardising the
\emph{reporting} of results from any source. For model and dataset
documentation, Model Cards \citep{mitchell-2019-modelcards} and
Datasheets \citep{gebru-2021-datasheets} established norms; no
analogous standard exists for evaluation runs. Three concurrent
2025 works---BenchmarkCards \citep{sokol2025benchmarkcards},
EvalCards \citep{dhar2025evalcards}, and Eval Factsheets
\citep{bordes2025factsheets}---propose narrative documentation
frameworks, but none is machine-validated or backed by a
large-scale audit of current confounder coverage. EvalSpec
(\S\ref{sec:evalspec}) provides SHACL-validated field
specifications grounded in that audit.
MLPerf \citep{mattson-2020-mlperf} demonstrates that standardised
evaluation is feasible at scale, but targets hardware benchmarking.

\paragraph{Causal methods and contamination.}
\citet{feder2022causal} survey causal inference in NLP where text
is treatment, outcome, or confounder---but not the evaluation
pipeline itself. To our knowledge, this is the first application of
a causal DAG to cross-source benchmark comparability, deriving
which metadata fields are \emph{necessary} for score attribution.
Benchmark contamination \citep{sainz-2023-contamination} is a
parallel source of cross-source divergence that documentation
alone cannot resolve; we focus on configuration confounding, but
note that contamination and prompt-format differences may
interact.

\section{Methodology}\label{sec:methodology}
% ===================================================================

\subsection{Schema, Pipeline, and Collision Detection}\label{sec:schema}

We adopt the EEE schema as-is \citep{evaleval-2026}; each record
contains four blocks (\texttt{model\_info},
\texttt{eval\_library}, \texttt{source\_metadata},
\texttt{evaluation\_results}). A \emph{cross-source collision
pair} $(m, b, s_1, s_2)$ arises when model~$m$ is evaluated on
benchmark~$b$ by two distinct sources, with score delta
$\Delta = \text{score}_{s_1} - \text{score}_{s_2}$.
\emph{Metadata coverage} for a field~$f$ is the fraction of
records where $f$ contains a non-trivial value.

The pipeline ingests each source via a dedicated converter
(source~$\to$~EEE JSON~$\to$~schema validation~$\to$~collision
detection~$\to$~coverage analysis). Sources: 8 leaderboards
(OLv2, AlpacaEval~2, Chatbot Arena, BigCodeBench, EvalPlus,
BFCL, SWE-Bench, WildBench, MT-Bench), 1 model-card source
(HuggingFace YAML \texttt{model-index}, benchmark-rich at 156
but model-poor at 11), and Papers With Code
(576 clean records from 1{,}350 raw, post-artefact removal;
\S\ref{sec:within}). Implementation: 4 framework adapters
(2{,}975~LOC) for lm-evaluation-harness, HELM, and Inspect~AI,
plus 7 leaderboard scrapers (3{,}268~LOC). All 29{,}331 records
pass \texttt{jsonschema} validation; duplicates use the composite
key (\texttt{model\_id}, \texttt{benchmark}, \texttt{source}).
For collision detection, we normalise IDs (lowercase, strip
\texttt{-hf} and shot annotations), group by $(m,b)$, and emit
all cross-source pairs with metadata-match annotations; full
procedure in Appendix~\ref{app:collision_procedure}.

\subsection{EvalSpec: A Specification for Evaluation Runs}\label{sec:evalspec}

EvalSpec v0.1 is a JSON-LD vocabulary (extending schema.org,
Croissant-compatible) whose required fields are derived from
causal necessity: the coverage analysis (\S\ref{sec:coverage})
and attribution failures (\S\ref{sec:collisions}) identify the
variables that must be recorded to make cross-source comparisons
identifiable under the DAG in \S\ref{sec:causal}. Three tiers:
\textbf{Required} (EvalSpec-R): \texttt{model\_id},
\texttt{benchmark\_id}, \texttt{scoring\_mode}
(\texttt{log\_likelihood} $|$ \texttt{generation} $|$
\texttt{preference} $|$ \texttt{execution}),
\texttt{eval\_library.\{name,version\}}, \texttt{n\_shot},
\texttt{date}, \texttt{random\_seed}.
\textbf{Recommended} (for attribution):
\texttt{prompt\_template} (SHA-256 hash), \texttt{temperature},
\texttt{top\_p}, \texttt{quantization}, \texttt{hardware},
\texttt{software\_environment}.
\textbf{Optional} (for full reproducibility):
\texttt{provenance\_link}, \texttt{contamination\_check},
\texttt{compute\_hours}. Compliance is enforced via SHACL
shape constraints; full field list in
Appendix~\ref{app:evalspec}.

Retrofitting EvalSpec to the 29{,}331 records yields 0\%
compliance on \texttt{prompt\_template} and \texttt{temperature}
(once artefacts are excluded) and $\sim$2\% on
\texttt{eval\_library.version} (unknown in 8 of 11 sources).
A reference validator is released at
\url{https://github.com/evaleval/every\_eval\_ever}.

\subsection{Metadata Coverage (H1)}\label{sec:coverage}

Table~\ref{tab:coverage} and Figure~\ref{fig:coverage} report
coverage rates for five metadata fields across all sources.

\paragraph{Headline figures are dominated by OLv2.}
Because OLv2 contributes 91\% of records, headline rates can
mislead. Excluding OLv2 (2{,}541 records from 10 sources),
n-shot coverage drops to 62.2\%, chain-of-thought to 1.1\%,
temperature to 0.2\%, and prompt template to 0.6\%; excluding
both OLv2 and PWC (1{,}965 records), chain-of-thought,
temperature, and prompt template are all 0.0\%
(Table~\ref{tab:ablation}). Outside a single dominant source,
nearly all evaluation-context metadata is absent.

\paragraph{Well-documented fields.}
\textbf{N-shot} (96.7\% with OLv2) is documented in all
leaderboards with few-shot benchmarks; the gap comes from
preference-based sources (Chatbot Arena, WildBench, MT-Bench)
where the concept does not apply. \textbf{Harness identity}
(98\%) is identified in all dedicated leaderboards; the 2\% gap
comes from PWC (harness genuinely unknown) and HF Model Cards
(32\%, after we tightened parsing to exclude
\texttt{library\_name} values that name \emph{inference} frameworks
rather than evaluation harnesses). \textbf{Crucially, no source
documents the harness \emph{version}}: all 29{,}331 records
carry \texttt{eval\_library.version = "unknown"}, an
ecosystem-wide gap.

\paragraph{Severely under-documented fields.}
\textbf{Chain-of-thought} (76.3\%) is documented only in OLv2
(83.4\%) and partially in PWC (4.9\%); all other sources: 0\%.
\textbf{Temperature} ($<$0.1\%): only 6/29{,}331 records document
it, all from PWC. \textbf{Prompt template} ($<$0.1\%): 14 records
contain prompt information (all PWC)---the most impactful
undocumented axis \citep{alzahrani-2024-benchmarks}. Manual audit
confirms that all 14 non-null \texttt{prompt\_template} values
are extraction artefacts; the \emph{valid} coverage rate is
therefore 0/29{,}331 (0.00\%), the most consequential metadata
gap in the dataset. Table~\ref{tab:ablation} confirms the
qualitative pattern is stable across source ablations.

\subsection{Within-Source Conflicts and Pipeline Fragility (H4)}\label{sec:within}

Before cross-source analysis, we audited within-source
consistency. Of 1,350 raw PWC records, 774 (57\%) were extraction
artefacts or duplicates---parameter counts parsed as scores,
variant tags routed to metadata fields---requiring removal. After
cleaning, only 1~within-source conflict remains. This confirms
H4: schema-valid pipelines produce semantically invalid records
at non-trivial rates. Full artefact taxonomy in
Appendix~\ref{app:artefacts}.

\subsection{The Structural Wall (H2)}\label{sec:wall}

Cross-source comparison requires both benchmark and model
overlap. Of the $\binom{11}{2} = 55$ source pairs, only 4 share
any benchmarks (HF Model Card~$\times$~OLv2, HF Model
Card~$\times$~PWC, OLv2~$\times$~PWC, EvalPlus~$\times$~HF Model
Card); the remaining 51 share \emph{zero}. Even where benchmarks
overlap, Jaccard similarity between model sets is below 0.11 for
all source pairs. OLv2 evaluates 4{,}465 models, but only 15 also
appear in PWC (by model ID), and just 1 shares both
model and benchmark. The result is 16 collision
pairs from 29{,}331 records---a 0.05\% yield
(Fig.~\ref{fig:overlap}).

\paragraph{Is fragmentation structural or accidental?}
We compare against a null model in which each source randomly
samples its model--benchmark pairs from the shared universe
(analytical birthday-paradox formula, preserving per-source
sizes).\footnote{$E = \sum_{i<j} R_i R_j / U$ with
$U = |\text{models}| \times |\text{benchmarks}|$. Earlier draft
simulations sampling from the full Cartesian product yielded
$\sim$272 collisions; the current formulation is more
conservative because it respects empirical per-source sparsity.}
The expected count is $69 \pm 8$; the observed 16 yields
$z = -6.4$ ($p < 0.001$), consistent with structural
fragmentation.

\paragraph{OLv2 dependence.}
The signal depends critically on OLv2. Excluding it leaves 2{,}541
records with 5~observed vs.\ 2.7~expected collisions ($z = 1.4$,
n.s.)---above random, not below. A leave-two-out analysis
(Appendix~\ref{app:leave_two_out}) confirms: 8/10~non-OLv2
ablations show more collisions than expected; none reaches
$p < 0.05$ in the fragmentation direction. \textbf{H2 characterises
an OLv2-dominated ecosystem, not a universal property.} Why OLv2
produces this disjoint population is an open question with
several candidate explanations (self-directed submission
attracting small-scale open-weight developers; specialised
leaderboards drawing commercial providers; OLv2's general-
capability benchmark scope); disentangling them requires
submission-log data that is not publicly available. Under strict
normalisation the finding strengthens ($z = -7.6$); qualitative
conclusions are invariant.

\subsection{Cross-Source Collisions and Documentation as a
Reliability Signal (H3)}\label{sec:collisions}

Of 16 collision pairs, 8 show $\Delta = 0.00$ (likely copied
scores); the remaining 8 independent pairs constitute our
evidence base (Table~\ref{tab:collisions}, Appendix~\ref{app:tables}).

\paragraph{Score gaps.}
The most extreme is Qwen2.5-72B-Instruct on GPQA: 16.67 (OLv2,
lm\_eval) vs.\ 49.0 (PWC, unknown)---a 32.3-point gap verified
against the original paper. Further gaps: MBPP+ (3.9),
HumanEval+ (3.0). The five Tulu-3-8B pairs show
$|\Delta| \leq 0.23$; these are confirmed independent (OLv2 via
lm\_eval for all submitted models versus HF Model Card populated
by the model authors from their vllm-based runs).

\paragraph{Documentation as a reliability signal.}
We computed a per-pair metadata completeness score (sum of
documented fields across harness, n-shot, CoT, temperature, and
prompt template; range 0--5) and the absolute divergence
$|\Delta|$ (Table~\ref{tab:attribution_extended}). Completeness
varied from 0 (Qwen2.5-72B) to 2 (all Tulu-3-8B pairs);
$|\Delta|$ ranged 0.07--32.33~pp. Across this near-exhaustive
set---confounded by model identity (the low-delta group is
entirely Tulu-3-8B) and source quality (the high-delta group
involves PWC, our least reliable source)---Spearman
$\rho = -0.871$ ($n=8$, $p = 0.005$; Fig.~\ref{fig:completeness}).
The five Tulu-3-8B pairs share a model family and two sources,
so effective DoF is approximately 2--3, not 8; we report the
$p$-value descriptively. The practical implication: in the
absence of re-evaluation capability, metadata completeness is
the best available proxy for cross-source trustworthiness, a
preliminary observation that larger EEE-schema datasets could
confirm.

\paragraph{First-party vs.\ third-party asymmetry.}
The five Tulu-3-8B pairs compare first-party (authors, vllm-based,
HF Model Card) against third-party (OLv2, lm\_eval) evaluation.
Mean first-party advantage is $-0.032$~pp (range $[-0.23, +0.19]$),
with 2/5 higher first-party. Direction inconsistent, magnitude
negligible---suggesting that for well-documented evaluations
using compatible harnesses, first- and third-party scores
converge.

\paragraph{Attribution gaps and scoring mode.}
Temperature and prompt template are unknown in \emph{every}
pair; n-shot is documented for only 5/8 (all Tulu-3-8B).
The GPQA gap is not a temperature or prompt-template problem:
OLv2 uses log-likelihood ranking via lm\_eval, while the PWC
score (verified against arXiv:2412.15115) reflects
generation-based evaluation with answer extraction. These
paradigms are not interchangeable and can produce divergences of
30+ points on the same benchmark. Current EEE has no way to
distinguish them; we propose
\texttt{evaluation\_results.scoring\_mode} as a required field
with four values---\texttt{log\_likelihood}, \texttt{generation},
\texttt{preference}, \texttt{execution} (Table~\ref{tab:terminology},
row~$\dagger$).

\subsection{Controlled Configuration Sensitivity}\label{sec:experiment}

The observational finding ($\rho = \spearmanrho{}$, confounded by
model identity and source quality) is consistent with the causal
DAG in \S\ref{sec:causal} but cannot confirm it: the association
could reflect model-family consistency (the Tulu-3-8B cluster
dominates the low-divergence group). To test whether within-source
configuration variation could mechanically produce cross-source
divergences of up to \gpqagap{}~points, we conducted a controlled
experiment.

\paragraph{Design.}
We evaluate \expmodels{}~instruction-tuned open-weight models
(Mistral-7B-Instruct-v0.3, Qwen2.5-7B-Instruct,
Llama-3.1-8B-Instruct) on
\expbenches{}~benchmarks spanning two scoring paradigms---GSM8K
\citep{cobbe-2021-gsm8k} (generative) and MMLU
\citep{hendrycks-2021-mmlu} (loglikelihood)---under a factorial
design: temperature $\{0.0, 0.7\}$ $\times$ prompt format
$\{$plain, instruct, cot$\}$ $\times$ n-shot $\{0, 5\}$, with
three random seeds per generative cell (MMLU is deterministic
given the same prompt). The
dataset comprises \expruns{}~runs
(\expgenruns{}~generative, \expllruns{}~loglikelihood), each
logged as an EvalSpec-R compliant record. Following
\citet{cinelli2020sensitivity}, we compute the partial $R^2$ of
each axis on score residuals (after model fixed effects) and
compare against the overturn bound
$\rho^2 = \overturnbound{}$.

\paragraph{Configuration effects fall below the overturn bound.}
On 5-shot GSM8K (where all three models produce extractable answers),
mean within-cell variation is $\tempeffectfive{}$~pp across
temperature and $\fmteffectfive{}$~pp across prompt format, both
an order of magnitude below the \gpqagap{}~point cross-source
divergence (Fig.~\ref{fig:config_vs_crosssource}). Seed variance
at fixed configuration averages $\noisefloor{}$~pp
(max $\noisefloormax{}$~pp across 24~cells), establishing the
noise floor. The Cinelli--Hazlett regression yields partial
$R^2 = \prtwotempfive{}$ (temperature) and $\prtwofmtfive{}$
(prompt format)---both well below $\overturnbound{}$
(Fig.~\ref{fig:sensitivity}). An unmeasured within-source
confounder would need to be 4--10$\times$ stronger than the axes
we measured to overturn the observational finding, a magnitude
inconsistent with the controlled literature on harness choice
\citep{alzahrani-2024-benchmarks, biderman-2024-lessons}.

\paragraph{Caveats.}
\textit{(n-shot on generative benchmarks.)} Including 0-shot
runs, n-shot explains $R^2 = \prtwonshotall{}$---above the
bound---but this reflects a threshold effect specific to
Mistral-7B-Instruct, which fails to produce extractable answers
on 0-shot GSM8K under lm-evaluation-harness's default extraction
(the apparent effect is ``no output'' vs.\ ``output scoring
$\sim$35\%,'' not a continuous in-context-learning gradient). We
therefore restrict the primary analysis to the 5-shot subset.
\textit{(Loglikelihood temperature invariance.)} On MMLU,
temperature has no effect on score by construction. Documenting
temperature is inconsequential for loglikelihood benchmarks,
and the metadata gap in \S\ref{sec:coverage} is most consequential
for generative benchmarks---including several collision pairs in
Table~\ref{tab:collisions} (MBPP+, HumanEval+).

Together, these results support the causal interpretation of
the observational finding: within-source configuration variation
is not large enough to produce 30+ point cross-source gaps.
Such gaps are more plausibly explained by undocumented
differences in harness, scoring mode, or prompt template than by
benchmark noise.

\section{Discussion}\label{sec:discussion}
% ===================================================================

\subsection{Why Documentation Is the Only Identification Strategy}

The H1 finding (0\% valid coverage for prompt template and
temperature) shows that the two highest-impact evaluation
confounders \citep{alzahrani-2024-benchmarks,
biderman-2024-lessons} are universally unobserved. Under the DAG
in \S\ref{sec:causal}, these unobserved variables constitute
open backdoor paths from configuration $C$ to observed score
$S$: cross-source comparisons where they are absent conflate
model capability with evaluation procedure. The H2 and H4
findings together eliminate the two alternatives to recording
$C$. Independent re-evaluation at scale is structurally
impossible (the required model--benchmark overlap does not
exist); automated ingestion cannot be trusted semantically
without post-hoc auditing (57\% PWC artefact rate). Documentation
is therefore not aspirational best practice but the only
available identification strategy, analogous to
pre-ClinicalTrials.gov clinical protocols---where, in the
absence of independent verification, mandatory protocol
recording substituted for replication. EvalSpec plays the
analogous role for LLM evaluation.

\subsection{EvalSpec as Backdoor-Blocking}

Recording EvalSpec Required-tier fields is equivalent to blocking
the highest-impact backdoor paths from $C$ to $S$. The GPQA
walk-through illustrates (Table~\ref{tab:backdoor}): had both
sources recorded \texttt{scoring\_mode}, the 32.3-point gap would
have been immediately attributable to evaluation paradigm rather
than capability. The Tulu-3-8B pairs demonstrate the other end:
with harness and n-shot documented (2 of 5 paths blocked),
cross-source scores converge to $|\Delta| = 0.14$---more than two orders
of magnitude below the Qwen2.5-72B gap. The controlled experiment
(\S\ref{sec:experiment}) quantifies the residual risk: partial
$R^2$ for temperature and prompt format
($\prtwotempfive{}, \prtwofmtfive{}$) falls well below the
overturn bound $\overturnbound{}$, confirming that the measured
configuration axes cannot mechanically produce 30+ point gaps.

\paragraph{Recommendations.}
\textbf{(R1)} Leaderboard maintainers should record Required-tier
EvalSpec fields at evaluation runtime. Temperature is one float
per run; \texttt{prompt\_template} is one SHA-256 hash. Both are
already present in the runtime environment and require only
logging. \textbf{(R2)} Model developers should ship EvalSpec-R
compliant evaluation files alongside model releases. The
Tulu-3-8B pairs show that recording harness and n-shot alone
drives mean $|\Delta|$ to 0.12. \textbf{(R3)} Schema and platform
designers should adopt \texttt{scoring\_mode} as a schema
primitive: no combination of other fields distinguishes
log-likelihood from generation-based evaluation, and the GPQA gap
is unresolvable without it. Because platforms already record
harness and n-shot, the structural barrier to recording
temperature and prompt template is incentives, not schema
availability; we therefore recommend leaderboard submission
systems \emph{require} EvalSpec-R compliance as a condition of
listing.

\paragraph{Threats to validity.}\label{sec:threats}
OLv2 contributes 91\% of records; excluding it changes headline
coverage figures but not qualitative conclusions. The GPQA
collision depends on PWC (verified against arXiv:2412.15115); the
32-point gap reflects scoring-mode divergence. The
reliability-signal result ($\rho = -0.871$, $n = 8$, effective
$n \approx 3$) is confounded and illustrative rather than
definitive. Full threats analysis in Appendix~\ref{app:threats}.

% ===================================================================
\section{Conclusion}\label{sec:conclusion}
% ===================================================================

The LLM evaluation ecosystem has an unmeasured confounder
problem. \textbf{H1~confirmed}: prompt template and temperature
have 0\% valid coverage across \totalrecords{}~records, making
observed scores causally uninterpretable as comparisons of
capability. \textbf{H2~conditionally confirmed} (OLv2-driven,
$z = 1.4$ n.s.\ without it): structural fragmentation
(16~vs.\ 69~expected collisions) makes independent verification
impossible at scale. \textbf{H3~preliminary evidence} ($n = 8$,
confounded): partial confounder recording coincides with more
than two orders of magnitude lower divergence ($|\Delta|$
0.14 vs.\ 32.3~pp), supported by a controlled experiment showing partial
$R^2$ values for temperature ($\prtwotempfive{}$) and prompt
format ($\prtwofmtfive{}$) fall below the overturn bound
(\overturnbound{}). \textbf{H4~confirmed}: 57\% of PWC records
are extraction artefacts that pass schema validation.

Documentation is the only available identification strategy in
an ecosystem where independent re-evaluation is structurally
impossible. \textbf{EvalSpec v0.1} (\S\ref{sec:evalspec},
Appendix~\ref{app:evalspec}) converts the five evaluation
confounders into required recorded fields grounded in causal
necessity. Without \texttt{scoring\_mode}, 32-point gaps remain
unexplained; without \texttt{prompt\_template} and
\texttt{temperature}, attribution is permanently incomplete. We
release dataset, pipeline, schema, and analysis code under
CC-BY-4.0.

% ===================================================================
\section*{Limitations}
% ===================================================================

The EEE schema does not enforce normalisation mode, pass@$k$, or
LLM-as-judge configuration; our dataset is a temporal snapshot.
The reliability-signal finding ($\rho = -0.871$, $n = 8$) is
confounded by model identity (the low-delta group is a single
model family) and source quality; effective DoF is approximately
2--3, and the result should be treated as a hypothesis to be
tested with larger collision datasets.

The controlled experiment (\S\ref{sec:experiment}) covers
\expruns{}~runs on \expmodels{}~models.
70B-class models would require multi-GPU
infrastructure beyond our single-A100 Colab budget. The 0-shot
GSM8K subset is uninformative for Mistral-7B-Instruct
(extraction-incompatible outputs yield 0), so we report 5-shot as
the primary specification. The overturn bound $\overturnbound{}$
derives from the observational $\rho^2$ and inherits its
confounds; the experiment establishes that measured configuration
axes fall below the bound but does not rule out unmeasured axes
(scoring mode, tokeniser differences) that larger studies could
quantify.

\section{Collision Detection Procedure}\label{app:collision_procedure}

Given evaluation records $R$, we:
(1)~\textbf{Normalise} model IDs: lowercase, strip \texttt{-hf}
suffixes, unify separators.
(2)~\textbf{Normalise} benchmarks: lowercase, strip shot
annotations (e.g., ``GPQA (0-shot)'' $\rightarrow$ ``gpqa'').
(3)~\textbf{Group} by (model, benchmark).
(4)~\textbf{Select} groups in $\geq$2 sources.
(5)~Emit all $\binom{k}{2}$ pairs with score delta and
metadata-match annotations.

\section{Extraction Artefact Taxonomy}\label{app:artefacts}

Manual audit of 50~PWC records identified three artefact types, each
requiring a distinct mitigation strategy.

\paragraph{(a) Parameter-count leakage.}
Model size identifiers---most commonly parameter-count suffixes
such as ``2.5B'', ``7B'', or ``70B''---are inadvertently parsed
into the numeric \texttt{score} field when extraction logic
ingests model name strings alongside score fields from
unstructured HTML tables. This artefact type accounts for
193~automated conflicts detected in our pipeline (score values
inconsistent with the expected range for the benchmark). The
root cause is that PWC's result-table HTML does not enforce
type separation between model descriptors and score values.
Proposed mitigation: a score range validator that rejects values
above 100 and flags values matching model-size patterns
(e.g., integer or decimal values that match known parameter-count
suffixes) before schema validation is applied. Such a validator
would have caught all 193 conflicts automatically.

\paragraph{(b) Variant-tag leakage.}
Model variant names---strings such as ``instruct'', ``chat'',
``v1.5'', or hyphenated version identifiers---are routed to the
\texttt{prompt\_template} field rather than to
\texttt{model\_info.variant} or discarded. This occurs because
variant-tag strings pass all schema type and format checks for
\texttt{prompt\_template} (both are free-text strings); the
artefact is therefore undetectable by schema validation alone.
The practical consequence is that the 14 nominally non-null
\texttt{prompt\_template} values in our dataset are artefacts of
this type (combined with type~(c)), inflating the apparent
coverage rate. Proposed mitigation: a whitelist of valid
\texttt{prompt\_template} formats (e.g., known format identifiers
such as ``mcq\_v2'' or ``alpaca''); any free-text string
containing hyphens, version numbers, or model-size patterns
should trigger a routing warning and be redirected to a
staging field pending manual review.

\paragraph{(c) CoT-label misrouting.}
Chain-of-thought descriptors---strings such as ``chain-of-thought'',
``CoT'', or ``step-by-step''---are parsed to
\texttt{prompt\_template} instead of the intended destination
\texttt{additional\_details.cot}. Like type~(b), CoT labels
are valid free-text strings that pass schema validation; the
misrouting is a pipeline routing error rather than a schema
violation. The consequence is that CoT status---already poorly
documented in our dataset---is doubly obscured: the field that
should carry it (\texttt{additional\_details.cot}) is empty,
while the field it erroneously populates
(\texttt{prompt\_template}) will be rejected if type~(b)
mitigations are applied. Proposed mitigation: the
\texttt{additional\_details.cot} field should be typed as
boolean; any string value in \texttt{prompt\_template} matching
a list of known CoT descriptors (maintained as a small vocabulary)
should trigger a routing warning and be re-evaluated for
reassignment to the CoT field.

Types (b) and (c) pass all automated checks including schema
validation, demonstrating that schema compliance is a necessary
but not sufficient condition for semantic validity.

\section{Extended Threats to Validity}\label{app:threats}

\paragraph{Source composition.}
OLv2 contributes 91\% of records. Removing it changes n-shot
coverage from 96.7\% to 62.2\% and CoT from 76.3\% to 1.1\%.
Temperature and prompt template remain absent across all
ablations.

\paragraph{PWC quality.}
We removed 774~PWC records as artefacts. The GPQA collision
($|\Delta|=32.3$) was verified against arXiv:2412.15115. The gap
reflects scoring-mode mismatch (log-likelihood vs.\
generation-based) rather than metadata failure alone.

\paragraph{Reliability signal confounds.}
% PRIORITY 2: confound disclosure precedes statistic.
The association between completeness and $|\Delta|$
($\rho = -0.871$, $n = 8$, effective $n \approx 3$) is
confounded in two ways. First, the low-delta group
is entirely one model family (Tulu-3-8B), so the association may
reflect model-family consistency rather than a documentation
effect. Second, the high-delta group involves PWC, which has
known quality issues. A clean test would require collision pairs
drawn from multiple independent model families with varying
documentation levels. We flag this as the primary threat to the
reliability-signal interpretation.

\paragraph{Normalisation.}
Varying strictness yields 6--16 collision pairs; conclusions are
invariant.

\section*{Appendix F: EvalSpec Schema (v0.1)}\label{app:evalspec}

EvalSpec v0.1 is released as a JSON-LD context file at [URL~TBD]
under CC-BY-4.0. The schema extends schema.org and is compatible
with Croissant (MLCommons, NeurIPS~2024) metadata records.
SHACL shapes for automated validation are included in the
repository alongside the dataset release. The three compliance
tiers---Required (R), Recommended (Rec), and Full (F)---map to
metadata completeness scores 1--2, 3--4, and 5 respectively on
the 0--5 scale used in \S\ref{sec:coverage} and
\S\ref{sec:collisions}: an EvalSpec-R record provides enough
information to identify the evaluation paradigm and harness;
an EvalSpec-F record provides enough information to reproduce
the evaluation run.

The \texttt{scoring\_mode} field is marked Required in EvalSpec
v0.1 despite being absent from the current EEE schema. We
recommend its addition to EEE as a first-class field alongside
the existing \texttt{generation\_config} fields. The four
enumerated values (\texttt{log\_likelihood}, \texttt{generation},
\texttt{preference}, \texttt{execution}) are exhaustive for
current LLM evaluation paradigms; an \texttt{other} value with
a mandatory free-text description is provided for edge cases.
The GPQA 32.3-point gap demonstrates why this field is Required
rather than Recommended: no combination of temperature, prompt
template, or harness fields can distinguish between
log-likelihood and generation-based evaluation paradigms, so its
absence makes the highest-impact attribution problem permanently
unresolvable regardless of compliance with other tiers.
The validator maps completeness scores to predicted
divergence risk using the $\rho = -0.871$ observational
association from \S\ref{sec:collisions}: completeness 0 corresponds to
high risk ($|\Delta|$ up to 32~pp), completeness 1--2 to
medium risk, and completeness 3--5 to low risk
($|\Delta| \leq 0.23$~pp), pending confirmation with larger
collision datasets.
